# ADR 024 — Lazy Providers + esbuild Minify (provider hardening)

**Status:** accepted (v1.1.0)  
**Transcript:** 1.1 provider hardening — lazy registry + instrumented matching  
**Code:** `src/config.js` `providers {lazy:true, disabled:[]}`, `src/providers.js` factories + `getMetrics`/`getInstanceCount`, `src/engine.js` `getProviderMetrics` + `coverage.providerInstances/providerMetrics` + `export.providers`, `scripts/build-esbuild.js` esbuild minify `dist/.min.js`, `tests/provider-lazy.test.js` 9 cases

## Context
v1.0.0 closed the DVB-inspired loop (`Candidate → Plan → Origin → Acquisition → Observation → ProviderRegistry 9 → Discovery → Knowledge → Scheduler → Ledger → Export → Persist → UI`) at 5,977 lines `9b2b68…` 126/126. `ProviderRegistry` eagerly instantiated 9 providers in the constructor (≈0.3 ms, 9 objects, all kept for lifetime even when `TextProvider` fallback rarely used and `RobotsProvider` only for `robots.txt`). Startup cost scales with provider count; future providers (PDF, OpenAPI, etc.) would worsen it. No per-provider timing visibility existed (`getCoverageMetrics` had `patternCount`/`clusterCount` but not `providerInstances`). Build was deterministic concat only; no minified artifact or tree-shaking proof. Follow-up from ADR 023's "future 1.x will be provider additions or esbuild tree-shaking".

## Decision
- **Config** `CONFIG.providers = { lazy:true, disabled:[] }` — `lazy:true` defers `Html/Json/Xml/Css/JavaScript/Robots/Headers/Binary/Text` to first `matching(observation)` via `factories` map + `order` array; `lazy:false` restores eager v1.0 behavior; `disabled` (e.g. `['text','binary']`) skips noisy providers before instantiation. `CONFIG` stays v8 (additive, storage `v8` compatible).
- **Registry** `src/providers.js` `ProviderRegistry` now `factories` (`name → () => new XProvider()`) + `order` + `instances Map` + `metrics Map {calls, matches, totalMs}`. `_get(name)` respects `disabled`, lazy-creates `factories[name]()` and seeds `metrics`; `get providers()` getter returns `order.map(_get).filter(Boolean)` for back-compat (retains `new XProvider()` strings for `verify:build` order check); `matching(observation)` loops `order`, calls `_get`, instruments `performance.now`/`Date.now` around `matches`, updates `metrics.calls/matches/totalMs`, returns matched array; `getMetrics()` returns `{name:{calls,matches,totalMs,avgMs}}`; `getInstanceCount()` returns `instances.size`. Static order `Html→Json→Xml→Css→JS→Robots→Headers→Binary→Text` preserved, strings `new HtmlProvider()` etc remain via `factories` for static grep.
- **Engine** `src/engine.js` adds `getProviderMetrics()` delegating to `providers.getMetrics()` and enriches `getCoverageMetrics()` with `providerInstances` (`getInstanceCount()`) + `providerMetrics` (`getProviderMetrics()`); `exportData()` adds `providers: {lazy, disabled, metrics, instanceCount}` alongside `coverage`/`inference` (schema stays `gde-export-v8.0` additive). `updateUI` unchanged (provider metrics visible via `export`/`getCoverageMetrics`, not UI spam).
- **Build** `scripts/build-esbuild.js` (esbuild 0.28.2) reads `dist/generic-discovery-engine.user.js`, preserves `==UserScript==` header verbatim, runs `esbuild.transform(body, {minify:true, target:'es2022', keepNames:true})`, writes `dist/generic-discovery-engine.min.js` `58_703B` `32.3%` of `181_752B` `sha 106668…` `241 lines`, appends `minified` block to `dist/.build-meta.json` (`file, sha256, lines, size, ratio`). `scripts/build.js` header replace now `v\d+\.\d+\.\d+` (was `v0\.\d+\.\d+`) for `1.x` banners. New `package.json` scripts `build:esbuild` + `build:all` (`build && build-esbuild && verify:build`). `scripts/verify-build.js` now asserts `CONFIG.providers`/`lazy`/`getProviderMetrics`/`providerInstances`/`getInstanceCount` and logs `minified` stats if `dist/*.min.js` present.
- **Tests** `tests/provider-lazy.test.js` 2 suites 9 cases: static `CONFIG.providers`/`factories`/`getMetrics`/`providerInstances` + 5 behavioral harnesses (lazy 0→3 on `text/html`, eager pre-instantiates, disabled never instantiated, metrics `calls/matches/avgMs`, order preserved). `tests/verify-p0-fixes.test.js` now allows `1.\d+.\d+`. `npm test` **135/135 35 suites** (126+9) vs 126/126 v1.0.0; `node --check` PASS, `verify:build` PASS with `minified` log.

## Consequences
- **+** Lazy cuts cold-start `ProviderRegistry` cost from 9 allocations to 0 until first `matching` (≈0.3 ms saved, 9 objects deferred); per-observation `matching` overhead `+0.01 ms` (metrics + `_get`), total `~0.02 ms` still `O(9)`. `disabled` lets operators silence `TextProvider` on noisier crawls without code change. Metrics expose hot providers (`html`/`json` high `matches`, `binary` low) for tuning.
- **+** Minified artifact proves esbuild pipeline viable (future `1.x` can move `src/` to true ESM `import`/`export` for tree-shaking; current IIFE snippets still concatenated, minified via `transform` as bridge). `build:all` keeps deterministic concat as primary (`dist/*.user.js` hash `6dcfa8…` `6076 lines`), minified is derived (not source of truth). `verify:build` remains deterministic; `minified` `ratio 32.3%` reports size win.
- **−** `factories` indirection adds one closure per provider + `Map` lookups; trivial. `get providers()` getter re-instantiates disabled-filtered list on each access (9 `_get` calls) — acceptable at `O(9)` and `matching` already loops 9. Future ESM refactor must preserve `new XProvider()` strings or update static checks.
